# Rodada de aceite de memória — 8M entidades (2026-08-13)

**Veredito: APROVADA.** A pergunta central do M1 — o dataset inteiro cabe em
menos de 1 GiB de RSS, com o heap desacoplado do volume de dados? — está
respondida com folga.

## Comando

```
GOMEMLIMIT=512MiB GOGC=100 ingest-bench \
    -data <disco real>/run-8m -entities 8000000 \
    -steady 30s -rate 0 -queries 4 -checkpoint-every 500000 \
    -heap-baseline rep-1m-ckpt.json -report rep-8m.json
```

Ambiente: Intel Core 7 150U (12 threads), Linux 6.8, Go 1.26.5, NVMe.
Corpus determinístico do `radiusgen` (seed 42) com o YAML de produção.

## Achado operacional: checkpoint não é opcional para o orçamento de memória

A primeira rodada de 1M **reprovou** o §110: heap de 36,5 MiB contra 2,8 MiB
na rodada de 100k — 13,19x de heap para 10x de dados, ou seja, heap crescendo
com o dataset, exatamente o que a arquitetura promete não fazer.

A causa é o overlay de locations, que vive em heap até um checkpoint aplicá-lo
ao mmap. Sem checkpoint, o overlay acumula uma entrada por row: ~36 bytes por
row (1M rows → 36 MiB; extrapolando, 8M → ~290 MiB, ainda dentro do teto, mas
consumindo 30% do orçamento sem necessidade e violando o §110).

Repetindo a rodada de 1M **com** `-checkpoint-every 200000`: heap 2,7 MiB
contra 2,8 MiB da rodada de 100k — 0,97x de heap para 10x de dados. Desacoplado.

Por isso o `-checkpoint-every` passou a ter default 500.000 no harness: rodar
sem checkpoint mede um cenário que a operação real não tem, e reprova o §110
por um motivo que não é da arquitetura. Fica registrado como recomendação de
operação: **checkpoint periódico é o mecanismo que drena o overlay**, não só
uma otimização de recovery.

## Reprodução

Duas rodadas, a menor primeiro (o gate §110 exige a referência):

```
ingest-bench -data <disco>/run-1m -entities 1000000 -steady 15s -report rep-1m.json
ingest-bench -data <disco>/run-8m -entities 8000000 -steady 30s -queries 4 \
    -heap-baseline rep-1m.json -report rep-8m.json
```

`-data` precisa apontar para DISCO REAL: são 6,35 GiB de segmentos e índices
com `fallocate` de verdade. Em tmpfs a medição perde o sentido (o dataset
entraria no próprio RSS) e a máquina trava.
