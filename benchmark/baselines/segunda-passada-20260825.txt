// Linha de base da SEGUNDA PASSADA (extração e descoberta) — 2026-08-25.
//
// Por que esta bancada existe: nenhum benchmark do projeto exercitava o
// caminho aninhado. O YAML dos micro-benchmarks
// (testdata/radius.materialization.yaml) não tem um único campo `type: json`,
// então a busca por caminho, a descoberta e a resolução de tipo — o caminho
// mais quente do dataset real — eram os únicos sem instrumento.
//
// O que ela mede: um documento de 11 chaves, a ordem de grandeza do piloto,
// com os três tipos que aparecem lá e um objeto aninhado. Em REGIME: as
// colunas já registradas no dicionário e o tipo já fixado.
//
// Como reproduzir:
//   go test ./internal/materializer/ -run '^$' \
//     -bench 'BenchmarkParse(Com|Sem)Descoberta' -benchmem -benchtime=20000x -count=6
//
// Ambiente: Intel Core 7 150U (12 threads), Linux 6.8, Go 1.26.5.
//
// LEITURA. A subtração é o número que importa: pelas MEDIANAS abaixo,
// ~2.925 ns com descoberta contra ~1.456 ns sem, a segunda passada custa
// ~1,47 us por evento — cerca de METADE do Parse de um evento com documento.
// A 500 ev/s do piloto isso são ~0,74 ms de CPU por segundo de relógio. Zero
// alocação nos dois lados, que é o que o gate do pacote já exigia e esta
// bancada confirma sob carga.
//
// ERRATA DA PRÓPRIA SESSÃO, e ela vale como método: a primeira redação deste
// cabeçalho dizia "~5,97 us, 66% do Parse", tirados de UMA rodada de cada
// bancada. A rodada de seis desmentiu os dois números. Medição única aqui é
// ruído frio, não sinal — use a mediana, e prefira benchstat a olhar linha a
// linha.
//
// PARA QUE ELA SERVE ADIANTE: o contador por coluna do bloco de densidade
// incrementaria uma vez por coluna derivada por evento — 11 vezes aqui — no
// caminho mais quente do produto. A promessa de que esse custo "sai de medição,
// não de raciocínio" não tinha instrumento antes disto.
//
// SEGUNDO USO, 26/08/2026 — a COERÇÃO PARA TEXTO. Os números abaixo continuam
// sendo a linha de base e não foram reescritos; o que segue é o registro de que
// ela foi usada de novo, para o que ela foi construída. A mudança acrescenta,
// por coluna derivada por evento, um teste de forma (f.Kind contra a forma
// nativa do tipo alvo) e, só nas colunas que de fato coergem, um segundo
// atomic.Add. Rodadas de -count=6 antes e depois, mesma máquina e mesma sessão,
// comparadas com benchstat: ParseComDescoberta 3,244 us → 3,308 us (p=0.818) e
// ParseSemDescoberta 1,506 us → 1,497 us (p=0.974) — nenhuma das duas distingue
// o antes do depois, e os dois lados seguem em 0 B/op e 0 allocs/op.
//
// A leitura honesta: com a variância desta bancada (±9% a ±37% no p50), ela NÃO
// resolveria uma regressão de poucos por cento. O que ela afirma é o que a
// decisão precisava — não há degradação de ordem de grandeza, e a alocação
// continua em zero, que é o gate duro do pacote.
//
